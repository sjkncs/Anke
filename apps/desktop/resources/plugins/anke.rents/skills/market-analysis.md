Query imported ShenzhenRents data before reporting rents. Keep demo data separate.
Listing descriptive statistics do not constitute the thesis model or its market
benchmark. For that task use same-period/submarket comparable matching, hedonic
community/time fixed effects, and evidence-based listing/transaction calibration;
state whether each step is proposed, runnable, estimated or validated. Never
invent a listing premium or use a district median as a quality-adjusted benchmark.
Separate listing/transaction and whole/shared strata. Use yuan per square metre
per month for comparable projects. Report dates, sample counts and missing fields.
Never infer transaction rents from listings or invent market coverage.

For Findesk financial/news tasks, first use FindeskCapabilities with
action=cookbook to choose a scenario, then use its exact id as query to retrieve
the complete official minimal template. Do not discover ordinary task parameters
one field at a time or reconstruct the template. Run the smallest example first;
expand symbols, fields and dates only after successful delivery and coverage
checks. For macroSeries replace YOUR_EDB_CODE with a code from the dictionary;
never invent a code or interpret an example as a local rent observation.
Read action=plans and the relevant capability contract before execution. Public plan pools
are not live account balances. Use documented authenticated entitlement before
choosing concurrency or task size. Missing quota pools remain unknown. Keep
plan permission, channel availability and data coverage separate. A financial
data subscription does not establish community-level Shenzhen rental coverage.
