# Lifelong learning library and cloud workspace

The service launcher orders Knowledge Library, Cloud Drive, then Research Center in the existing lifelong-learning group. Migration version 2 adds Cloud Drive once, preserves renamed services and does not recreate previously removed personal services. Existing Bot configuration remains available through service management.

Knowledge Library defaults to Obsidian. The backend discovers registered Windows vaults through the current user's Obsidian registry, validates each folder and its `.obsidian` directory, and chooses the most recently opened available vault. Settings > Connectors > Lifelong learning allows a different vault, ima, or a custom provider. No note is uploaded during discovery. Search matches Markdown filenames and paths by default. Optional content search reads at most 200 notes within a 16 MiB budget, shows matching snippets and reports incomplete coverage or unreadable files. Both modes skip hidden entries and symbolic links, return 50 rows per page and inspect at most 5,000 entries. Reading one note is limited to 500 KB and rejects traversal and paths resolving outside the vault. The note view can open the note in Obsidian or put its vault identifier and path into the matching assistant's composer for review before sending. Search/read requests can carry a vault identifier and reject stale references after a vault switch. This is local retrieval, not an embedding index or cloud synchronization.

Cloud Drive defaults to Google Drive, with Claude Projects and GitHub workspace links. Links do not establish authentication or synchronization. The user can select an explicitly Bot-authorized MCP connector and check its actual tools. ima and other products need a compatible authorized connector; no undocumented endpoint is assumed. All remote actions continue through the existing per-Bot MCP bridge and tool allowlist. Upload, deletion, publication and account authorization are not performed by this change.

The `team.learning.library` panel route supports status, configure, search, read and tools. The `anke_learning_library` agent tool exposes read operations only to the matching knowledge/cloud service Bot in a private conversation. Provider settings use the existing team save queue and field-specific rollback; credentials remain in the existing vault, never in these settings.

Validation: `node --test tests/learning-library.cjs tests/personal-services.cjs tests/anke-services.cjs tests/service-launcher-ui.cjs tests/learning-library-ui.cjs`. Browser tests use isolated fixtures. Real local discovery is checked separately without reading personal notes. Authenticated Google/Claude/ima operations and native desktop acceptance require separate verification.

References: [Obsidian data storage](https://obsidian.md/help/data-storage), [Claude Google Workspace connectors](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors). Accessed 2026-11-13.

## Full-renderer acceptance, 2026-11-13

Saving a vault or provider now remounts the library immediately and discards the previous note view. Provider selection controls are disabled while saving, and mismatched provider/vault/connector combinations fail validation. Tool inspection uses the bridge's Bot-filtered `list` operation rather than unfiltered discovery and renders tool names and descriptions as regular rows. A failed GitHub status request no longer prevents lifelong-learning settings from loading.

`tests/service-shortcuts-ui.cjs` mounts the complete Anke renderer, uses the real library backend with two temporary fixture vaults, reads a note, switches vaults, verifies the old content disappears, reloads the page and verifies the setting persisted on disk. It also opens connector settings during a simulated GitHub outage. Screenshots are saved at `output/playwright/service-shortcuts/learning-library.png` and `learning-connectors.png`. `tests/settings-routes-ui.cjs` covers all eleven settings pages. These checks do not restart or certify the user's native desktop session and do not read personal note contents.

The full-renderer fixture also searches by note body, renders a matching snippet and places the selected note reference in the assistant composer without creating a job. Backend fixtures cover stale-vault rejection, the 200-note limit and the 16 MiB content budget, including title matches after content coverage is exhausted. Current local profile inspection found knowledge/cloud service Bots but no connectors authorized to them; cloud file access remains unverified.
